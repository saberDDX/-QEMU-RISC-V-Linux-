# 一页背诵卡

**项目定位**：复用 Quard Star 板级支持，做系统构建、启动参数和应用自启动；不是从零移植 BSP。

**链路**：QEMU 虚拟硬件 → Mask ROM → lowlevelboot → OpenSBI → U-Boot → Linux + DTB → 根文件系统 → BusyBox init → rcS → bsp_demo / Shell。

**职责**：OpenSBI 提供 SBI；U-Boot 加载并启动内核；Linux 管硬件和资源；rootfs 提供用户空间；DTB 描述硬件。

**三种特权级**：M 态 OpenSBI；S 态 U-Boot 和 Linux；U 态 BusyBox 与应用。具体模式以配置和启动日志为准。

**交叉编译**：x86_64 宿主执行交叉编译器，产出 riscv64 程序。Linux 程序用匹配的目标 libc；裸机固件用嵌入式 C 库。

**实际磁盘**：第一分区 FAT32 放 Image、DTB、boot.scr；第二分区 ext4 放 init、BusyBox、库、配置及 bsp_demo。

**启动脚本**：`configs/boot.cmd` → mkimage → boot.scr → U-Boot 执行 load / setenv / booti。bootcmd 是执行命令；bootargs 是内核命令行。

**本次参数**：root=/dev/vda2；console=ttyS0；loglevel=7 → 4。看 `/proc/cmdline` 和 `/proc/sys/kernel/printk`，不只看宿主文件。

**自启动**：PID 1 的 BusyBox init 读 inittab，sysinit 调 rcS；先挂 proc 再执行 bsp_demo。程序调用 uname、读取 /proc/uptime，输出后退出。

**验收命令（目标 Shell）**：`uname -m`；`uname -r`；`cat /proc/cmdline`；`cat /proc/sys/kernel/printk`；`/usr/bin/bsp_demo manual`。

**个人改动文件**：`configs/boot.cmd`、`app/bsp_demo.c`、`rootfs/etc/init.d/rcS`。每项回答最后补一句“我通过哪份目标日志确认”。

**新增调试补充**：QEMU gdbstub（非 KGDB）；`-S` 暂停、`-gdb` 监听；vmlinux 提供匹配符号；hbreak / continue / next / bt / print / info registers / detach。实测停在 start_kernel 和 run_init_process，后者参数是 /sbin/init。详见 GDB启动调试.md。
