# 对照 RK3576 项目的扩展取舍

第一个项目已有：ARM64 内核/模块/DTB 部署、platform/input、GPIO 双边沿中断与 delayed work 消抖、I2C MPU6050、字符设备、V4L2 MMAP。

因此第二个项目定位为“RISC-V 最小系统构建与启动链路调试”。不重复添加教学字符设备或另一个设备树匹配例子。

以下依据固定上游提交的真实目录 `tutorial/index.rst` 和对应正文：

| 官方章节 | 与第一个项目的关系 | 本次决定 |
| --- | --- | --- |
| 扩展 4：QEMU gdbstub 调试 | 补充源码断点、寄存器、栈和启动阶段定位；与外设实现有区别 | **选这一项，已实测** |
| 扩展 1：KGDB 内核/模块调试 | 以后可用于真实板卡驱动调试；有额外串口与内核侧调试器配置 | 暂缓，不把 gdbstub 实验写成 KGDB 经验 |
| 扩展 5：QEMU CAN | 汽车/工业方向有针对性；教程主要是已有 CAN 驱动与 SocketCAN 的集成验证 | 暂缓，未明确目标岗位，不为凑数添加 |
| ch24—25：网络与 SSH | 提升远程开发便利性，但作为简历独立成果较弱 | 不单列模块 |
| ch21 / ch7：FreeRTOS / OpenSBI Domain | 差异大，但需要额外理解端口层、特权级和域配置，时间投入较高 | 只保留已存在的上游启动依赖 |
| ch16 / ch23：Framebuffer / Qt | 第一项目已有采集与显示链路，对 BSP 驱动实习的新增价值有限 | 不添加 |
| ch14 / ch22：ELF / 工具链 / C 库 | 对模块和应用部署有帮助，但更适合支撑现有构建经历 | 维持必要理解，不另开项目 |

目录未提供独立完整的 A/B 更新与回滚专题，本次不把自行设计的升级方案当作官方现成模块添加。

最终只增加 **QEMU gdbstub 内核启动调试**。这是一项补充能力，不把“重复实现了几个基础接口”当成第二个项目的主要差异。
