# 简历和项目讲述

以下表述对应本次已验收的范围；建议亲手复现核心操作后用于面试。

## 简历条目（精简版）

**基于 QEMU/RISC-V 的嵌入式 Linux 构建与启动调试**

- 基于开源 Quard Star 板级支持，完成 U-Boot、Linux/DTB 与 BusyBox 根文件系统构建，打通从启动固件到串口 Shell 的启动流程。
- 定制 U-Boot 启动脚本中的内核日志参数，通过目标 `/proc/cmdline` 和内核日志阈值确认生效。
- 交叉编译系统信息 C 程序，集成目标动态库和 BusyBox init 初始化脚本，实现开机自启动，整理构建入口与串口运行记录。

- 使用 QEMU gdbstub 与 GDB 设置内核启动断点，查看寄存器、调用栈及 init 参数，验证内核入口到用户空间的交接。

这是系统构建、应用集成和虚拟环境启动调试项目，不包含独立 BSP 移植、新外设驱动开发或真实芯片初始化。

## 一分钟讲述

我基于 Quard Star 开源项目做了一个精简的 RISC-V Linux 构建项目。QEMU 提供虚拟硬件，上游早期固件加载 OpenSBI 和 U-Boot，U-Boot 从 virtio 磁盘加载内核和设备树，Linux 挂载第二分区的根文件系统，再由 BusyBox init 启动用户空间。

我的主要工作是固定源码版本、适配无 root 的云构建环境和镜像制作流程，完成必要组件构建。定制内容有两项：把启动脚本的 loglevel 从 7 改成 4，并在目标系统验证；编写 bsp_demo 获取架构、内核版本和 uptime，在 rcS 挂载 proc 后调用，实现一次性开机自启动。

我还通过 QEMU 的 GDB 接口在 start_kernel 和 run_init_process 停住，检查源码、寄存器、调用栈和 /sbin/init 参数，再放行系统进入 Shell。

我保留了构建脚本、配置差异和目标运行记录。板级模型、固件框架及驱动是复用上游的，我没有将它们描述成自己的移植成果。

## 你必须亲手完成的三件事

1. 运行 `scripts/run.sh`，进入目标 Shell，执行三条基本确认命令。
2. 手动执行 `/usr/bin/bsp_demo manual`，再重启看到 autostart。
3. 指着 `configs/boot.cmd` 和 `rootfs/etc/init.d/rcS` 解释自己的两类改动。

如果还不能完成这三件事，先用“正在完成/学习”表述，并继续投递，不用因为扩展专题无限拖延求职。
