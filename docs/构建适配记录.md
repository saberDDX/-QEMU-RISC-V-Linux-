# 构建适配记录

基线来自 QQxiaoming/quard_star_tutorial，提交 `083d2dd8337adc0c7fd0522e1d16e075b9f11365`。通过 GitHub HTTPS 归档下载，完整性检查与 SHA256 已记录。原站 ch2 当前返回 403，采用同仓库 `tutorial/ch2.md` 作为对照。历史 ch2 举例是 QEMU 6.0，当前固定提交已是 QEMU 8.0；本项目以固定源码为准，不直接复制历史章节的目录名。

| 问题 | 原因 | 本工程处理 |
| --- | --- | --- |
| 系统没有管理员权限 | 无法 apt 系统安装、loop 挂载 | APT 验证后下载并解包到工作区；FAT、ext4 及 MBR 均在普通文件中制作 |
| 通用 QEMU 不含板卡 | quard-star 为上游自定义机型 | 从上游 QEMU 8.0 源码构建并检查 machine help |
| trusted_domain 链接 R_RISCV_HI20 溢出 | 预编译 newlib 是 medlow，固件链接在高地址 | 从 newlib 4.1.0 源码构建 medany C 库，链接时优先选用；不改板级地址和 Domain 配置 |
| U-Boot 独立输出目录找不到 Logo | 上游汇编以相对路径 incbin 位图 | 在生成目录复制已有位图，保留原配置，不开发图形功能 |
| BusyBox tc 编译失败 | 旧 applet 使用新版 Linux UAPI 已删除的 CBQ 定义 | 关闭不在项目范围内的 CONFIG_TC，其他已有基础配置保留 |
| 重定位后的 Linux 工具链找不到 libc | Debian ld 脚本含绝对目标路径 | 使用 GCC 包装器传入正确 sysroot |
| QEMU GLib/pixman 链接失败 | 解包 dev 包后缺少同目录运行库，误用静态库或断链 | 补齐对应运行包并重新进行 Meson 依赖检测 |

trusted_domain 依赖的 FreeRTOS 代码按上游原样保留，只作为启动基线依赖。不列为本人的 FreeRTOS 移植或学习成果。

`qemu-riscv64` 用户态模拟器调用宿主内核，不能用它输出的内核版本证明 Linux 6.1.11 已启动。本项目验收使用自定义 QEMU 整机中的串口日志。

首次整机启动暴露了函数跟踪初始化问题：Linux 6.1.11 在本组合（GCC 14.2 / 上游 RISC-V ftrace 配置）下于 `ftrace_init` 阶段 panic。失败日志见 `evidence/boot-ftrace-failure.log`。当时的最小范围不使用 ftrace 函数跟踪，采用生成配置 `CONFIG_FTRACE=n` 并重建，保留真实失败记录。没有通过跳过目标启动验证来掩盖失败。

关闭 FTRACE 后，GCC 14 / binutils 2.44 组合构建的内核仍在早期初始化停顿。通过本地 QEMU monitor 寄存器确认它重复停在同一执行位置，未将其记为通过。改用现有官方 GCC 11.1 / binutils 2.36.1 工具链构建内核；生成配置关闭 FTRACE 和可选 GCC_PLUGINS。内核最终使用官方 Linux GCC 11.1 / binutils 2.36.1 工具链。中途裸机链接器不支持 vDSO 所需的共享目标，因此没有采用它完成内核构建；BusyBox 与应用仍用 Linux GCC 14.2 和配套 glibc。切换编译器的目的在于使用与历史工程更匹配的组合，不声称已定位到某一编译器源码缺陷。

最终 Linux GCC 11.1 组合已进入目标 Shell；`uname -m` 为 riscv64，`uname -r` 为 6.1.11，程序自动和手动运行均通过。GCC 14 两次失败日志保留为历史诊断，最终使用的编译器与配置以 `evidence/linux.config` 为准。

保留上游驱动时，串口中可见音频 ASoC DAI 探测失败及声卡 deferred probe；音频不在本次范围内，未将其记为通过。QEMU 的 NIC 无 peer 提示来自本项目禁用网络连接。上述消息与已经验证的块设备、根文件系统、Shell 和程序运行区分记录，不据此声称整板全部外设可用。
