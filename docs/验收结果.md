## T3：程序与自启动

源码：`app/bsp_demo.c`。安装位置：`/usr/bin/bsp_demo`。

定制系统在未输入手动命令前自动输出：

```text
[INIT] proc/sys/dev ready; starting bsp_demo
[BSP_DEMO] started mode=autostart
[BSP_DEMO] machine=riscv64 kernel=6.1.11 uptime=1.67 seconds
[INIT] initialization complete
```

进入目标 Shell 后手动运行：

```text
quard-star# /usr/bin/bsp_demo manual
[BSP_DEMO] started mode=manual
[BSP_DEMO] machine=riscv64 kernel=6.1.11 uptime=30.00 seconds
```

调用路径：Linux → BusyBox init → `/etc/inittab` 的 sysinit → `/etc/init.d/rcS` → `/usr/bin/bsp_demo autostart`。程序在 proc 挂载后执行。

## 后续补充：QEMU gdbstub 启动调试

在现有内核、固件、DTB 和根文件系统上直接验证，无需重编内核。

1. 启动 -S 暂停的 QEMU，GDB 加载相同 vmlinux，通过宿主回环地址连接。
2. 命中 start_kernel 硬件断点，查看源码、PC/SP、调用栈，next 到下一源码行，并读取 init_task.comm。
3. 命中 run_init_process 硬件断点，读取 init_filename 为 /sbin/init，并查看调用栈。
4. 删除断点并 detach 后系统继续启动，进入 Shell；uname、loglevel=4 和 bsp_demo 手动/自启动均正常。
5. 正常 sync / poweroff，QEMU 退出。

完整证据：evidence/gdb-startup.log 与 evidence/boot-after-gdb.log。只声明 QEMU gdbstub，未将此实验记作真实板卡 KGDB 或实际驱动故障修复。
